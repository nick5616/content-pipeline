# Canon: M2 implementation plan (Ingest)

Status: **approved 2026-10-28** ("yes to all": E1 to E5 as recommended, plus the M1 schema sign-off). Decisions recorded as D26 to D30.

M2 turns a file you drop in into a sanitized, verified, content-addressed blob plus a draft item, entirely locally. Nothing in M2 talks to GCS.

---

## 0. Decisions

### 0.1 Need your call

| # | Question | Recommendation |
|---|---|---|
| E1 | **HEIC** (iPhone photos). exiftool can strip HEIC, but ffmpeg 6.1 can't decode it, and browsers can't show it. | **Accept it.** Keep the sanitized HEIC as the source blob, and have M4 make WebP derivatives with `heif-dec` from `libheif-examples` (in Ubuntu's apt; bootstrap adds it, doctor checks it). Every image a site shows is a WebP derivative anyway, so the source format doesn't matter to any site. The alternative is to reject HEIC with "export as JPEG". That's simpler, but you'd convert every phone photo by hand. |
| E2 | **When originals reach the archive (D14).** D14 says ingest uploads them, but the design doc says nothing reaches the cloud without a reviewed plan. | **Ingest stages the original locally; apply uploads it.** M2 copies the untouched original into `<cache>/originals/`, and M3 gets an `archive-original` plan op that runs first. That keeps "Apply is the only thing that touches the cloud", and the plan shows what's going to the archive. |
| E3 | **How the manifest remembers each original** (schema change, part of M1 sign-off). | Add `original` (the SHA-256 of the original bytes) to `assetRef`. The public projection drops it, and `public-manifest.schema.json` forbids it. Without it, apply can't know which originals belong to which blob, and re-ingesting a photo on the Mac would make a duplicate (different exiftool version, so different sanitized bytes, but the same original). |
| E4 | **What kind a dropped image becomes.** | **`photo` if the original had camera Make/Model, otherwise `artwork`.** This reads the original's metadata locally, before stripping. `--kind` and the UI override it. Video → `video`, audio → `track`, PDF → `writing`. |
| E5 | **Prefilling the draft's date from the original's capture time** (`DateTimeOriginal`, day precision). | **Yes, but only as a draft value you review.** It's useful for sorting, and nothing publishes without your review. Say no and dates start empty. |

### 0.2 Defaults I'll take unless you object

- **The verify gate fails closed.** Rather than a denylist of known-bad tags, every tag exiftool reports in the sanitized output must be on an allowlist of structural tags for that format (dimensions, orientation, color profile, codec info). Anything else stops the ingest with the tag's name. A new phone that invents a new GPS tag fails instead of leaking. The cost is the occasional false stop on a harmless tag, which we then add to the allowlist with a test.
- **Plus a denylist, for clear messages.** GPS, location, serial and owner/person tags (GPS*, *Location*, ISO6709, *SerialNumber, OwnerName, CameraOwnerName, Artist, Author, Creator, By-line, XPAuthor) are reported by name, as "GPS survived", not just "unknown tag".
- **Supported types (by magic bytes, never the extension):** JPEG, PNG, WebP, HEIC/HEIF (if E1), TIFF, GIF; MP4/MOV/M4V; MP3, M4A/AAC, AIFF, WAV, FLAC; PDF. Anything else is rejected with its detected type. Files whose extension lies, like the 13 JPEGs named `.HEIC` in `artandmedia`, are handled by type, and the blob gets the right extension.
- **Working manifest without sync.** M2 needs somewhere to put drafts, so it adds the local half of D6: `working.json` in the state dir, written atomically under a file lock, so `canon ingest` and `canon serve` can't clobber each other. Remote generations, `base.json` and pull stay in M3. On first run, an empty working manifest is created, with `profile.name` from a new config field `profileName`.
- **No SQLite in M2.** The blob cache is content-addressed and idempotent by construction, and a small sidecar index (original hash → sanitized blob) makes re-ingest a no-op. Ingest progress for the API lives in memory. SQLite arrives with jobs in M4.

## 1. What the experiments showed (2026-10-28, this machine's ffmpeg 6.1.1, exiftool 12.76, qpdf 11.9)

| Format | Doc's command | Result | Change |
|---|---|---|---|
| JPEG | `exiftool -all= -tagsFromFile @ -ColorSpaceTags -Orientation` | GPS, serial, owner, make/model, IPTC and XMP all gone; orientation kept. Byte-identical on rerun. | None |
| PNG | same | **A legacy `zTXt` "Raw profile type exif" chunk survives with GPS and serial inside it, and exiftool can't read it to warn.** | Go rewrites PNGs with a chunk allowlist (IHDR, PLTE, IDAT, IEND, tRNS, cHRM, gAMA, iCCP, sBIT, sRGB, pHYs, bKGD, plus APNG's acTL/fcTL/fdAT). The verify step parses chunks itself and fails on any text or eXIf chunk. |
| MOV/MP4 | `ffmpeg -map_metadata -1 -map_chapters -1 -c copy` | Keys, UserData and XMP location, make, model and serial gone. | Map **only** video and audio streams (`-map 0:v -map 0:a?`): `-map 0` would copy data and timed-metadata tracks (iPhone GPS trails live there) and subtitle tracks. Add `-fflags +bitexact -flags:v +bitexact -flags:a +bitexact`, which also zeroes creation dates and makes reruns byte-identical. |
| MP3 | same | ID3 gone. | Map `0:a` only. Otherwise the cover art (an attached JPEG with its own EXIF) is copied through. Add `-write_id3v2 0`. |
| AIFF/WAV | same | ID3 and ANNO chunks gone; **PCM samples byte-identical**. | `-write_id3v2 0`. Not `-id3v2_version 0`: the AIFF muxer rejects it. |
| PDF | `exiftool -all:all=` then qpdf | exiftool alone leaves the old Author and serial in the bytes, since its PDF edits are reversible. After `qpdf --deterministic-id` the decompressed file has none, and output is byte-identical on rerun. | Use `--deterministic-id` (and `--object-streams=generate`). |
| PDF images | n/a | **Neither tool strips EXIF inside embedded images** (a phone scan saved as a PDF). | Verify pulls every embedded JPEG stream out (`qpdf --show-object`/`--raw-stream-data`) and runs the image check on each one. Any hit is a hard stop: re-export the PDF. |

Hardening that falls out of this:
- **ffmpeg only reads local files:** `-protocol_whitelist file,pipe`, and the demuxer is forced from the sniffed type (`-f mov`, `-f mp3`, ...). Otherwise a playlist disguised as a video could make ffmpeg fetch URLs or read other local files.
- **No user config:** exiftool runs with `-config ""`, so `~/.ExifTool_config` can't change the output.
- **Timeouts and no shell:** every tool runs through `exec` with a timeout and no shell, on a temp copy. Originals are never opened for writing.

## 2. Pipeline

```
input (path or upload)
  -> stage:    stream into <cache>/tmp/<ulid>/in, hashing as it goes      (original sha256)
  -> dedupe:   original already known?  -> report existing item, stop
  -> detect:   magic bytes -> Type{Kind, MIME, Ext, Tool}                 (reject unsupported)
  -> sanitize: per type (exiftool / ffmpeg / exiftool+qpdf / Go PNG)      -> <tmp>/out
  -> verify:   exiftool -j -a -u -G1 -ee on out, allowlist + denylist,
               PNG chunk scan, A/V stream list, PDF embedded images        (hard gate)
  -> hash:     sha256(out) -> blob ref
  -> store:    <cache>/blobs/sha256/ab/cd/<hash>.<ext>                     (rename, atomic)
               <cache>/originals/sha256/ab/cd/<orig>.<ext>  (for E2's archive op)
  -> facts:    ffprobe / exiftool on out: dimensions, duration, sample rate
  -> draft:    new item in working.json (visibility draft)
```

Every step is idempotent. A crash leaves at most a `tmp/<ulid>/` folder, which the next run deletes. Blobs only appear by atomic rename after verify passes.

**Type-level guarantee.** The sanitize package returns a `Verified` value with an unexported constructor, and the only code that makes one is the verify gate. `blobstore.Put` accepts only `Verified`, and the originals store accepts only `Original`. An unsanitized file going into the blob store, which M3 uploads from, is then a compile error rather than a code-review catch.

Changes elsewhere:
- **Schemas:** `assetRef.original` (E3). The public schema forbids it. A new `archive-original` OpType in `openapi.yaml`, for M3.
- **Config:** `profileName`, and `maxIngestBytes` (default 8 GiB).
- **Bootstrap and doctor:** add `libheif-examples` / `heif-dec` (only if E1 is accepted).
- **`.gitignore`:** `testdata/_out/` is already ignored. Fixtures are generated there at test time.

## 4. Fixtures (`make-media.sh`, generated into `testdata/_out/`, cached by script hash)

Every fixture carries fake GPS (37.7749, -122.4194), serial `SN-FAKE-…`, owner "Fake Owner" and make/model, in every place that format can hold them:

- **JPEG:** EXIF, GPS, XMP, IPTC, and a 90° orientation that must survive.
- **PNG:** eXIf, tEXt Author, iTXt XMP with GPS, **zTXt raw EXIF profile with GPS** (the artandmedia case), and an iCCP profile that must survive.
- **JPEG named `photo.HEIC`:** detected as JPEG and stored as `.jpg`.
- **HEIC** (if E1): encoded with `heif-enc`, with EXIF GPS added by exiftool.
- **WebP, TIFF, GIF:** EXIF/XMP GPS.
- **MOV:** Keys location (ISO6709), UserData GPS, serial, artist, and **a subtitle track with GPS text**, which must be dropped.
- **MP3:** ID3 artist/comment and **cover art JPEG with GPS**, which must be dropped.
- **AIFF:** ID3 and ANNO. **WAV:** LIST/INFO. **FLAC:** Vorbis comments and a picture block.
- **PDF:** Info dict, XMP, **an incremental update that leaves old metadata in the bytes**, and a second PDF with **an embedded JPEG carrying GPS**. The second one must be rejected.
- **Unsupported and hostile:** an HLS playlist named `.mp4`, a ZIP, a truncated JPEG, and a zero-byte file.

## 5. Tests

| Property | Test |
|---|---|
| Private (the doc's privacy test) | For every fixture: the sanitized output has no GPS, serial or owner by exiftool, **and** a raw byte search (decompressing zlib streams and PNG zTXt/iTXt, and qpdf `--qdf` for PDFs) finds none of the planted strings. |
| Gate is a hard stop | An injected sanitizer that passes input through unchanged: every fixture fails verify, no blob is written, no draft is created, and the CLI exits non-zero naming the surviving tags. |
| Fail closed | A synthetic tag outside the allowlist (an XMP custom namespace) fails, even though no denylist matches it. |
| PDF images | A PDF with an embedded GPS JPEG is rejected, and the message says to re-export. |
| Preserved | JPEG orientation and ICC profile survive; PNG iCCP survives; audio samples and video packets are byte-identical before and after (ffmpeg `-f framemd5`). |
| Deterministic | Sanitizing the same input twice gives identical bytes and the same blob ref. |
| Detect | Table test on magic bytes, including the wrong-extension cases and every rejected type. |
| Idempotent ingest | Ingesting the same file twice: one blob, one draft, and the second run says "already ingested as <slug>". Ingesting two files with identical sanitized bytes gives one blob. |
| Originals untouched | Each source file's sha256 and mtime are unchanged after ingest. Its staged copy in `originals/` is byte-identical to it. |
| Draft | Valid against the manifest schema and `Validate`; kind follows E4; slugs dedupe (`sketch`, `sketch-2`); facts match the fixture (dimensions, duration). |
| Working manifest | Concurrent `Update`s from two processes both land (flock); a crash mid-write leaves the old file intact. |
| ffmpeg hardening | The HLS playlist named `.mp4` is rejected at detect, and ffmpeg is never started with a non-file protocol (checked through a recording exec stub). |
| API | `POST /api/ingest` with two files returns 202 and an IngestBatch; polling reaches `done`; an oversize upload gets 413; all of it is validated against `openapi.yaml`. |

**M2 is done when** all of the above pass in WSL, `canon ingest testdata/_out/*` turns every allowed fixture into a clean blob plus a draft and stops red on the hostile ones, and a second run changes nothing.

## Built (2026-10-28)

Everything above is in, with these additions found while building:
- **TIFF (D31):** `-all=` left Artist, ImageDescription, Make, Model and Software. Fixed with explicit IFD0 deletes, and caught by the fail-closed verify, not a denylist.
- **exiftool picks formats by extension:** a JPEG named `.HEIC` failed to sanitize until the input is hard-linked under its real extension.
- **PDF:** exiftool's `-ee` also finds GPS inside embedded images, so the hostile scan is rejected twice over; the PDF-image finding is listed first because it says what to do.
- **MP3:** sanitized packets are byte-identical, but timestamps shift by a constant tick (encoder delay); the packet test compares sizes and hashes.
- **Same picture, different metadata** sanitizes to one blob and one draft; M3 must still archive both originals (D34).
- **Pending libheif:** HEIC tests skip, and `canon doctor` fails `heif-dec`, until `libheif-examples` is installed. Then: run the HEIC test, record `heif-dec --version` as a fixture, and extend the allowlist if real HEIC structure tags show up.
- **Race detector:** runs in CI (needs cgo; this WSL has no C compiler).
