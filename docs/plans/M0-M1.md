### 0.1 Working manifest (D6)

- The private bucket's `manifest/manifest.json` is the only durable copy. Locally, the state dir holds `base.json` (the remote at generation G, plus G) and `working.json` (your edits on top of it). The state dir is `$XDG_STATE_HOME/canon`, never the repo.
- Every command that reads the manifest (`serve` start, `plan`, `apply`, item edits) first fetches the remote object's metadata: one request, no download.
  - **Remote generation == G:** use `working.json`.
  - **Remote moved, no local edits:** pull silently and fast-forward.
  - **Remote moved, local edits present:** stop. `canon diff` shows both sides; `canon pull --discard-local` takes the remote. v1 has no merging.
  - **GCS unreachable:** editing keeps working offline. `plan` and `apply` need the network anyway.
- First run on an empty bucket: `working.json` starts from an empty manifest at generation 0, and the first apply creates the remote object with `ifGenerationMatch=0`.

### 0.2 Findings that affect the plan

- **WSL has almost nothing installed.** git and Docker (via Docker Desktop) are present. Go, Node, ffmpeg, exiftool, qpdf, Task and jq are missing. `npm` and `gcloud` resolve to the **Windows** installs under `/mnt/c`, which breaks ADC: Go in WSL looks in `~/.config/gcloud`. `doctor` will fail any required tool that resolves under `/mnt/`.
- **`gs://artandmedia` is publicly readable** (`allUsers: objectViewer`), and **58 of its 121 images carried GPS**. **Fixed 2026-10-27:**
  - All 136 files were copied byte-for-byte, with metadata, to the new private `gs://artandmedia-originals` (public access prevention enforced, versioning on, 30-day soft delete).
  - Every public image was replaced in place with a stripped copy: pixel data hash unchanged, orientation, color profile and custom metadata kept, same URLs.
  - 13 files had the wrong extension (JPEGs named `.HEIC`/`.PNG`). One PNG kept EXIF in a legacy `zTXt` chunk. **Both cases go into the M2 fixtures:** detect by magic bytes, and drop PNG text chunks.
  - The MP3s only carry an `encoder` tag and were left alone.
  - The `private` object metadata still only hides pieces in the UI; those 3 files remain downloadable by URL.
- **There are two art metadata schemes on the same objects.** The holodeck reads `art-name`, `art-description`, `art-date`, `art-order` and `private`. Nickel Tools reads `created`, `description` and `private`. The bucket importer maps both and flags conflicts.
- **Open schema question resolved:** the holodeck galleries list GCS directly by folder (folder = collection id) and use object metadata. They do not go through `holodeck-art-api`.
- **`dj-crate/`** feeds the 3D site's DJ room (`src/components/rooms/studio/dj/crate.ts`). `scripts/build-dj-crate.mjs` encodes AIFF masters to 192 kbps MP3 with ffmpeg and runs classical DSP for BPM, beat grid, key and the waveform. See D15.
- **No per-project 3D settings exist today.** The showroom computes placement from index and ring physics, and colours come from hardcoded `CATEGORY_COLORS`. "Curie x3" and a recipe API are hardcoded `LAB_EXTRAS` in the 3D repo, not in `content.ts`. The importer can't read them; they become items by hand in M7.
- **There are four date parsers today, and they disagree.** The holodeck slices the raw string, so "Sometime in like Oct 2025" shows as "Sometim". Views will ship `date.display` and `date.sortKey` precomputed.

### 0.3 Resolved calls (approved 2026-10-27)

1. `EXPERIENCE` and `EDUCATION` move into the manifest as `profile.experience[]` and `profile.education[]`.
2. Duplicate categories (`Games`/`Gaming`, `Social Tools`/`Social App`): the importer proposes merging each pair, and you confirm in review.
3. `dj-crate` is in scope as the `holodeck-dj-room` surface (D15). This also partly answers the open music question: the DJ room's full tracks are public.

### 1.3 Interfaces

```go
// engine/config
type Config struct {
    Project, Region           string
    PrivateBucket, PublicBucket string
    ImpersonateServiceAccount string   // optional; ADC impersonation target
    CacheDir, StateDir        string   // default XDG cache/state + /canon
    Serve struct{ Port int }
}

// engine/toolchain
type Tool struct{ Name, Path, Version string }
func Lookup(ctx context.Context, name string) (Tool, error) // fails if Path is under /mnt/

// engine/doctor
type Check struct{ Name string; Status Status; Detail string } // Status: ok | warn | fail | skipped
type Report struct{ Checks []Check; Tools []Tool }
func Run(ctx context.Context, env Env) Report // Env injects lookPath, exec, gcs, fs for tests
```

**Doctor checks:**
- ffmpeg, ffprobe, exiftool and qpdf present, with versions written to `<state>/doctor.json`. A version change since the last run is a warning.
- Config valid.
- ADC present, and impersonation can mint a token.
- Each configured bucket is reachable (`Bucket.Attrs`). This is `skipped` while bucket names are unset.
- Cache and state dirs are writable.
- Docker is reachable (warn only, dev).

The only network calls are GCS and Google's token endpoints, which ADC needs.

**Localhost guard** (`api/guard.go`), applied to every route, including static files:
- Rejects any `Host` that isn't `127.0.0.1:<port>` or `localhost:<port>`. That includes `127.0.0.1.evil.com` and a missing Host.
- Requires `Authorization: Bearer <token>` on `/api/*`, compared in constant time. Static UI files are served without the token, since the token arrives in the fragment.
- Never sets any `Access-Control-*` header, and `OPTIONS` gets 405.
- Sets `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, and a strict CSP (`default-src 'self'`).

### 1.4 Bucket provisioning (`scripts/provision-buckets.sh`)

- Reads project, region, bucket names and the service account from config or flags. It has no defaults and refuses to run if any are unset.
- `--dry-run` (the default) prints the plan. `--apply` executes it.
- Every step is describe-then-create-or-update, so a second run makes no changes and says so:
  - **Both buckets:** uniform bucket-level access, object versioning on, soft delete 30 days.
  - **Private bucket:** public access prevention `enforced`.
  - **Public bucket:** `allUsers: roles/storage.objectViewer`, plus the CORS policy from D16.
  - **Archive bucket (D14):** public access prevention `enforced`, versioning on, no lifecycle rules. The service account gets `objectCreator` and `objectViewer` only, so it can never delete or overwrite an original.
  - **Service account `canon-apply@<project>`:** created if missing. It gets `roles/storage.objectAdmin` on the two buckets only, and you get `roles/iam.serviceAccountTokenCreator` on it.
- It never touches `artandmedia`.

### 2.2 Tooling (D4)

- **Source of truth:** JSON Schema 2020-12 files in `schema/`.
- **Validation authority:** `github.com/santhosh-tekuri/jsonschema/v6`, which supports all of 2020-12. Generated Go types are for ergonomics only; the validator decides what's valid.
- **Go types:** `github.com/omissis/go-jsonschema`. Schemas stick to a codegen-friendly subset: `kind` discriminates `facts` with `if/then` rules that the validator enforces and codegen ignores, and there's no deep `oneOf`.
- **TS and Zod:** `json-schema-to-zod`, with types taken from `z.infer`. That gives one output and no second type generator.
- **API:** OpenAPI 3.1 (its schema dialect is 2020-12, so it can `$ref` the same files).
  - The UI client uses `openapi-typescript` and `openapi-fetch`.
  - Go handlers are hand-written on `net/http`'s `ServeMux`.
  - A contract test using `pb33f/libopenapi-validator` checks every request and response in the handler tests against `openapi.yaml`.
  - I'm not using oapi-codegen because its 3.1 support is incomplete.
- **Drift check:** generated code is committed, and CI runs `task gen` and fails on any diff.

### 2.3 Manifest shape (top level)

```jsonc
{
  "schemaVersion": 1,
  "profile": { "name": "...", "headline": "...", "summary": "...", "links": { "github": "...", "linkedin": "...", "email": "..." } },
  "ownedDomains": ["nicolebelovoskey.com", "*.nicolebelovoskey.com", "rpg-quests.netlify.app", "..."],
  "taxonomy": {
    "categories": [{ "slug": "immersive-web", "label": "Immersive Web", "icon": "🌐" }],
    "tech": [], "mediums": [], "tags": [],
    "viewports": [{ "slug": "phone", "label": "Phone", "width": 393, "height": 852 }]
  },
  "surfaces": [{ "id": "software-portfolio", "label": "software.nicolebelovoskey.com", "baseUrl": "https://software.nicolebelovoskey.com" }],
  "items": [ /* sorted by id */ ]
}
```

- **Item:** as in the design doc. `id` is a ULID; `slug` is unique; `aliases` must not collide with any slug or other alias; `kind`; `visibility` is `draft` or `public`; `title`; `summary`; `why`; `date` is `{ value, label? }`.
- **More item fields:** `status`; `category`; `tech`, `tags` and `mediums` (taxonomy slugs); `facts` (validated by kind); `links[]`; `assets[]`; `copy`; `placements[]`; `members[]` (collections only); `richDescription` (`{ markdownBlob?, component? }`); `private` (private manifest only).
- **Link `rel`** is an enum: `live`, `source`, `backend-source`, `docs`, `video`, `listen`.
- **Placement:** `{ surface, key?, order?, featured?, hidden?, copy?, config }`. `key` is required when an item has more than one placement on the same surface.

**Semantic rules** (`Validate`, each with an invalid fixture):
- ids, slugs and aliases are unique.
- Taxonomy slugs exist.
- A placement's surface is registered, and its `config` passes that surface's placement schema.
- Two placements on the same surface need distinct keys.
- Collection members exist, are not the collection itself, and form no cycles.
- Preview and embed URLs are on owned domains (error); other links on non-owned domains are warnings shown in the plan.
- `date.value` is an ISO partial.
- Blob refs look like `sha256:<64 hex>`.
- `copy` only uses allowed fields (D8).
- `private` is absent from the public projection.

### 2.4 Surfaces: placement config and view (frozen in M1, built in M5)

Every view has the same envelope:

```
{ view, viewVersion, pipelineVersion, profile?, taxonomy (only slugs used in this view), entries[] }
```

**Every entry carries:**
- `id`, `slug`, `key`, `kind`, `title`, `summary`, `why`
- `date`: `{ value, label, display, sortKey }` or null
- `status`, `category` (as `{ slug, label, icon }`), `tech`, `tags`, `mediums`
- `links` (absolute URLs), `order`, `featured`

Entries are sorted by `order`, then `date.sortKey` descending, then `id`. Copy is already resolved.

### 2.6 `@canon/client`

`loadView(surface, { baseUrl, fetch? })` fetches `views/<surface>.json` and parses it with that view's Zod schema. It throws on a schema or `viewVersion` mismatch. `loadViewFromFile(path)` is for build-time baking. There are no runtime dependencies besides Zod.

### 2.7 M1 tests

| Property | Test |
|---|---|
| Schemas are valid | Every schema compiles under the 2020-12 metaschema; every `$ref` resolves. |
| Rules enforced | Table test: each fixture in `testdata/invalid/` fails with the expected problem code; each in `valid/` passes. One fixture per rule in 2.3. |
| Go and TS agree | Vitest loads the same fixtures through the generated Zod schemas, and the verdicts match `expectations.json`, which the Go test also checks. Semantic rules are Go-only and marked as such. |
| Deterministic | Marshal the same manifest twice: identical bytes. Marshal a manifest with shuffled items or keys: identical to the canonical file. No `<` HTML escapes; raw UTF-8 (emoji and `é` survive); trailing newline. |
| Round trip | Load, then Marshal, a canonical golden file: byte-identical. |
| IDs | `NewWith` gives deterministic ULIDs under a fixed clock and entropy, monotonic within the same millisecond. |
| Public schema | A public fixture that contains `private` or a draft fails `public-manifest.schema.json`. |
| Views | One golden view fixture per surface validates against its view schema in Go and in Zod. |
| API spec | `openapi.yaml` parses and validates as 3.1; every `operationId` has a CLI twin. |
| Client | `loadView` accepts the golden fixture, and rejects a wrong `viewVersion` or a missing field, with a readable error. |
| Codegen drift | CI: `task gen` followed by `git diff --exit-code`. |

**M1 is done when** all of the above pass and you've signed off on the schemas and `openapi.yaml`. After that, changing them is a versioned change: bump `viewVersion` or `schemaVersion`.

## 3. M2 to M8 outline (each gets a full plan before it starts)

- **M2 Ingest:**
  - The sanitizer and verify gate, as in the design doc.
  - Fixtures are synthetic images, video, audio and PDF generated by a script with fake GPS, serial and owner tags; nothing real is committed.
  - **HEIC** needs a decision: exiftool can strip HEIC, but browsers can't display it, so ingest either keeps the HEIC as the source plus a WebP derivative, or rejects it.
- **M3 Plan and apply:** remote listing, the pure diff, saved plans, generation preconditions, history snapshots, and the idempotency test against fake-gcs.
- **M4 Jobs:**
  - The recipes from the doc.
  - `thumb@v1` widths (320/800/1600) don't cover the holodeck, which loads 48/2048/3200 through the Netlify image CDN. The M4 plan proposes widths that cover both.
  - Jobs keyed by jobkey are idempotent across machines: if macOS and WSL both run a job, whichever runs first wins and the other skips.
  - **DJ recipes (D15):**
    - `dj-mp3@v1` produces a 192 kbps full-length MP3. That is different from `preview@v1`, which makes a 128 kbps MP3 plus a 30-second clip.
    - `djgrid@v1` produces BPM, first beat, start, key, Camelot and the 3-band waveform JSON. It's a Go port of the DSP in `build-dj-crate.mjs`. A test runs both on the same audio and requires matching BPM and key, and a first beat within 1 ms.
- **M5 Publish:** public projection, public copies, unpublish, and the seven view resolvers against the frozen schemas.
- **M6 UI:** the screens from the doc, built against `openapi.yaml`.
- **M7 Migration:**
  - `import content-ts` reads `content.ts` **statically** with the TypeScript compiler API, via a small Node script that runs nothing and executes no React. That way the `// TODO` and `// Private` comments become `private.notes`. Go does the mapping and validation.
  - `hide: true` entries become drafts, and About, Contact and Settings are skipped.
  - `import bucket gs://artandmedia` maps both metadata schemes, sanitizes (stripping the GPS found above), and drafts one artwork item per object, with membership in its folder's collection.
  - LAB_EXTRAS and the profile additions are entered by hand.
  - Sites move in this order: 3D world, then nickel-tools pages, then the desktop.
- **M8 GC and rollback:** as in the doc.
